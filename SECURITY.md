# Security Policy

## Supported versions

Only the latest GitHub release of Cleanup receives security fixes. Older
releases should be updated to the current version.

## Reporting a vulnerability

Please **do not** open a public issue for a security problem.

Use GitHub's private **Report a vulnerability** form on the repository's
Security tab. If private reporting is not available, contact the maintainer
privately through GitHub rather than posting in an issue or discussion.

Include as much of the following as you can:

- affected version or commit;
- steps to reproduce;
- expected and actual behaviour;
- potential impact;
- any suggested fix.

## What to expect

Reports are reviewed as soon as possible. You will get an acknowledgement and
an update when the issue is confirmed or rejected. If a fix is needed, it will
be released as a new version with a `vX.Y.Z` tag and a GitHub Release.

## Scope

This policy covers the plugin code in `cleanup/`. Vulnerabilities in WordPress
core, Composer dev dependencies or third-party libraries should be reported to
their respective maintainers.
